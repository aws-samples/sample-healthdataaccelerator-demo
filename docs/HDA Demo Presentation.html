Create or Edit a Patient Record

  2. Add a new encounter
  3. Add a clinical note
  4. Save — record is now in Aurora MySQL
Within 10 minutes, this data will automatically sync to HealthLake via FHIR API
OpenEMR Patient Record Form ⬆ SHOW IN BROWSER

What's Happening Behind the Scenes

  • Data written to Aurora MySQL (encrypted at rest)
  • OpenEMR FHIR endpoint updated automatically
  • Lambda sync polls every 10 min with _lastUpdated
  • New records pushed to HealthLake as FHIR R4 resources

Demo 5: Lake Formation — Access Control

No Access → Grant → Query

  1. AWS Console → Lake Formation
    Navigate to Data Permissions
  2. Login with restricted role — no SELECT grant on HealthLake tables
  3. Run Athena query — access denied ❌
  4. Grant the permission — add SELECT grant for the role
  5. Re-run same Athena query — patient data returns successfully ✅

What This Proves

  Fine-Grained Access Control

Lake Formation enforces who can see which data — down to row and column level. This is HIPAA "minimum necessary" built into the platform.

Role-Based Access Examples

Demo 6: Analytics with Athena

Query FHIR Data with SQL

  1. AWS Console → Athena — select the HealthLake database
  2. Show Iceberg tables — auto-generated from FHIR resources
  3. Run a query — population health insights
  4. Show Lake Formation — governed access controls
SELECT DISTINCT p.name[1].given[1] AS first_name, p.name[1].family AS last_name, p.gender, p.birthdate, date_diff('year', date(p.birthdate), current_date) AS age FROM patient p ORDER BY last_name LIMIT 20
Athena Query Results — FHIR Analytics ⬆ SHOW IN AWS CONSOLE

Key Points

  • Zero ETL — HealthLake auto-exports to Iceberg
  • Standard SQL — no FHIR knowledge required to query
  • Lake Formation — row/column-level access control
  • Feed results into QuickSight for dashboards

Full Architecture — What You Just Saw

Data Journey (End to End)

  1. Clinician enters data → OpenEMR → Aurora MySQL
  2. FHIR sync Lambda → polls every 10 min → pushes to HealthLake
  3. HealthLake → auto-exports to Iceberg → queryable via Athena
  4. Patient 360 Dashboard → queries HealthLake FHIR API
  5. Bedrock AI → generates clinical summaries from FHIR data
  6. Orthanc imaging → queried directly via DICOMweb
